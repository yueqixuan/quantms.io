# Project / Experiment Metadata

The project view captures experiment-level metadata for a QPX dataset -- project identity, file registry, instrument configuration, and software provenance. In v1.0 this information lives in a single `project.json` file. In v2.0 it is being replaced by `experiment.parquet`, a structured Parquet file that is easier to query and better aligned with the rest of the QPX ecosystem.

!!! note
    The v2.0 `experiment.parquet` format is a proposal under active development. The v1.0 `project.json` format remains the current production format generated by quantms.

---

## Current Format (v1.0): project.json

The `project.json` file is a single JSON document that stores project identity, sample summaries, instrument and enzyme lists, the file manifest, and software provenance.

### Schema

| Field | Description | Type |
|---|---|---|
| `project_accession` | Project accession identifier (e.g. `PXD014414`) | string |
| `project_title` | Title of the project | string |
| `project_description` | Description of the project | string |
| `project_sample_description` | Description of the project sample | string |
| `project_data_description` | Description of the project data | string |
| `project_pubmed_id` | PubMed ID associated with the project | int32 |
| `organisms` | List of organisms involved in the project | list[string], null |
| `organism_parts` | Parts of organisms studied | list[string], null |
| `diseases` | Diseases associated with the study | list[string], null |
| `cell_lines` | Cell lines used in the study | list[string], null |
| `instruments` | Instruments used for data acquisition | list[string] |
| `enzymes` | Enzymes used in the study | list[string] |
| `experiment_type` | Types of experiments conducted | list[string] |
| `acquisition_properties` | Properties of the data acquisition methods | list[key/value] |
| `quantms_files` | Files related to quantMS analysis | list[key/value] |
| `qpx_version` | Version of QPX | string |
| `software_provider` | Software used to generate the data | key/value |
| `comments` | Additional comments or notes | list[string] |

!!! tip "Reading project.json in Python"
    ```python
    import json

    with open("PXD014414.project.json") as f:
        project = json.load(f)

    print(project["project_accession"])   # PXD014414
    print(project["instruments"])          # ['Q Exactive HF']
    ```

## Proposed Format (v2.0): experiment.parquet

In v2.0, `project.json` is replaced by `experiment.parquet` -- a single-row Parquet file that stores experiment-level metadata using typed, structured columns instead of free-form JSON.

### Key changes from v1.0

| Aspect | v1.0 (`project.json`) | v2.0 (`experiment.parquet`) |
|---|---|---|
| **Format** | JSON | Apache Parquet |
| **Project identity** | Top-level JSON fields | Typed Parquet columns |
| **Aggregated biology** (`organisms`, `organism_parts`, `diseases`, `cell_lines`) | Stored redundantly as lists | Removed -- derived at query time via `SELECT DISTINCT` on [sdrf.parquet](sdrf.md) |
| **File registry** (`quantms_files`) | Explicit list in JSON | Replaced by glob-based file discovery + optional `file_manifest` column |
| **Searched modifications** | Not captured | Structured `searched_modifications` list |
| **Column semantics** | Not captured | `column_semantics` map defining the semantic level of each SDRF column |
| **Software version** | Nested key/value | Flat `software_provider` + `software_version` strings |

!!! warning "Aggregated lists are no longer stored"
    Fields like `organisms`, `organism_parts`, `diseases`, and `cell_lines` are **not** stored in `experiment.parquet`. These are redundant copies of information already present in the SDRF. In v2.0, derive them at query time:

    ```sql
    SELECT DISTINCT organism FROM sdrf
    ```

    This eliminates the risk of the project metadata drifting out of sync with the actual sample annotations.

### PyArrow Schema

```python
import pyarrow as pa

experiment_schema = pa.schema([
    pa.field("project_accession", pa.string()),
    pa.field("project_title", pa.string()),
    pa.field("project_description", pa.string(), nullable=True),
    pa.field("pubmed_id", pa.int32(), nullable=True),
    pa.field("instruments", pa.list_(pa.string())),
    pa.field("enzymes", pa.list_(pa.string())),
    pa.field("experiment_type", pa.list_(pa.string())),
    pa.field("acquisition_method", pa.string()),
    pa.field("searched_modifications", pa.list_(pa.struct([
        pa.field("name", pa.string()),
        pa.field("accession", pa.string()),
        pa.field("site", pa.string()),
        pa.field("type", pa.string()),
        pa.field("mass_delta", pa.float64(), nullable=True),
    ])), nullable=True),
    pa.field("file_manifest", pa.list_(pa.struct([
        pa.field("file_name", pa.string()),
        pa.field("file_category", pa.string()),
        pa.field("is_partitioned", pa.bool_()),
        pa.field("partition_fields", pa.list_(pa.string())),
    ])), nullable=True),
    pa.field("column_semantics", pa.map_(pa.string(), pa.string()), nullable=True),
    pa.field("software_provider", pa.string()),
    pa.field("software_version", pa.string()),
    pa.field("qpx_version", pa.string()),
])
```

### Field Reference

#### Core Identity

| Field | Description | Type | Required |
|---|---|---|---|
| `project_accession` | Project accession identifier | string | yes |
| `project_title` | Title of the project | string | yes |
| `project_description` | Description of the project | string, null | no |
| `pubmed_id` | PubMed ID associated with the project | int32, null | no |

#### Experimental Configuration

| Field | Description | Type | Required |
|---|---|---|---|
| `instruments` | Instruments used for data acquisition | list[string] | yes |
| `enzymes` | Enzymes used in the study | list[string] | yes |
| `experiment_type` | Types of experiments conducted (e.g. LFQ, TMT) | list[string] | yes |
| `acquisition_method` | Data acquisition method (e.g. `DDA`, `DIA`) | string | yes |

#### Searched Modifications

| Field | Description | Type | Required |
|---|---|---|---|
| `searched_modifications` | Modifications configured in the database search | list[struct], null | no |

Each struct in the list contains:

| Subfield | Description | Type |
|---|---|---|
| `name` | Human-readable modification name (e.g. `Oxidation`) | string |
| `accession` | Ontology accession (e.g. `UNIMOD:35`) | string |
| `site` | Residue or terminus (e.g. `M`, `N-term`) | string |
| `type` | `fixed` or `variable` | string |
| `mass_delta` | Mass shift in Daltons | float64, null |

!!! tip "Relationship to per-PSM modifications"
    The `searched_modifications` list captures what was configured in the search engine. For per-peptide modification evidence with localization scores, see the [Modifications](modifications.md) specification.

#### File Manifest

| Field | Description | Type | Required |
|---|---|---|---|
| `file_manifest` | Optional registry of QPX output files | list[struct], null | no |

Each struct in the list contains:

| Subfield | Description | Type |
|---|---|---|
| `file_name` | Name of the output file | string |
| `file_category` | Category of the file (e.g. `feature_file`, `psm_file`) | string |
| `is_partitioned` | Whether the file is partitioned into multiple parts | bool |
| `partition_fields` | Column names used for partitioning | list[string] |

!!! note
    The `file_manifest` column is optional. In v2.0, clients may also discover files by glob pattern (e.g. `PXD014414.*.parquet`) or query an external DuckDB catalog.

#### Metadata and Provenance

| Field | Description | Type | Required |
|---|---|---|---|
| `column_semantics` | Map from SDRF column name to its semantic level (`sample`, `file`, `factor`) | map(string, string), null | no |
| `software_provider` | Name of the software that generated the data | string | yes |
| `software_version` | Version of the software | string | yes |
| `qpx_version` | Version of the QPX format specification | string | yes |
